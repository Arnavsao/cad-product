Blocks, attributes and the library

B I BLOCKS

Define and place

B turns a selection and a base point into a definition; I inserts it with scale and rotation. The Blocks palette lists every definition in the drawing to drag in. Paste as block (Ctrl+Alt+V) defines and places in one step.

BEDIT BCLOSE X

Edit the definition

The block editor opens one definition in isolation; save with BCLOSE or answer the prompt on Esc, and every instance follows. X explodes an instance into plain entities when you need to.

LIB SYM FIND

Attributes, library, find

Blocks carry attributes: imported ATTDEF and ATTRIB values are kept, shown and editable, and FIND searches and replaces across text, MText, attribute values and table cells. The library holds symbols you reuse across drawings.

06

Layouts and plotting

Model space is where you draw at full size. A layout is a sheet of paper with viewports that frame the model at a scale; that is what gets plotted.

Model space and paper space

LAYOUT adds, renames and reorders layout tabs. MVIEW draws a viewport on the sheet and asks for its scale; viewports are objects, so you move them, drag a grip to resize them (scale preserved) and Delete them like anything else. Type MSPACE to pan, zoom and edit the model through the first viewport; PSPACE returns to the sheet, where title blocks and notes live. Every tool works in both spaces, and osnap only picks the space you are editing.

Page setup

PAGESETUP sets paper, orientation, plot offset, plot style and scale for the layout, and the same fields appear in the Plot dialog for a one-off. Lineweights can scale with the plot scale or stay absolute.

How an action is checked

  1. Validate. The request compiles to named tools; unknown actions, empty targets and missing permissions are rejected before anything runs.
  2. Classify. Each tool declares a risk class and the batch takes the highest.
  3. Confirm. Destructive batches wait for a yes; review batches show what they will touch.
  4. Commit as one step. The whole batch is a single command on the undo stack. Ctrl+Z removes it entirely.
  5. Log locally. Every resolved turn goes to an append-only audit log in this browser's IndexedDB. It never leaves your device.

09

Accounts and cloud

An account gives you a place for drawings, a version for every save, and a way to hand a drawing to someone else without emailing a file.

The life of a save

  1. Every {{ autosaveSeconds }} s

    Recovery snapshot

    If anything changed, the drawing is serialised to the browser's IndexedDB. This is crash insurance, not a cloud save: it does not create a version and does not touch the server.

  2. Ctrl+S

    Cloud save, one version

    Saves are explicit. Each one writes the DXF to your account and mints a new version; the dashboard's version history lists them all and restores any of them. Files up to 50 MB.

  3. Offline

    Queued in the browser

    If the network fails, the save lands in the local cache marked pending and the header says so. Press Ctrl+S again when you are back online; replay is deliberately manual so a stale copy is never pushed over someone else's work.

  4. Conflict

    Someone saved first

    Every save carries the version it started from. If the server has a newer one, it refuses rather than overwriting, and you choose:

    {{ a.label }}

Folders, trash, sharing

My Drawings holds folders you can nest and move; deleting sends a drawing to Trash, where it can be restored or the trash emptied. A view-only drawing still opens in a working editor; when you save, the result goes to a copy of your own.

Share a drawing directly with an email address or a whole organization, or make a link. Links are view or edit, expire after 7, 30 or 90 days or never, can be revoked, and can be emailed to up to ten people with a note straight from the dialog. Recipients open the drawing in their browser.

How the language is chosen

  1. The language this browser last chose, if any.
  2. Otherwise the browser's own language preferences, widened (de-AT becomes Deutsch).
  3. Otherwise English.
  4. Signing in applies the language stored on your account on top, so it follows you across devices.

Change it under Settings → Language. The option names are in each language's own script on purpose.

Translation status. English is the source. The other thirteen files are drafted following AutoCAD's established terminology per language and have not yet been reviewed by native-speaking drafters. Any string still missing from a language falls back to English rather than showing a key name. If a term reads wrong in your language, tell us.

Embedding the editor

The editor is a standalone Angular component with a small API. There are three ways to put it in front of your users.

1. Run it separately and link to it

Deploy CADO on its own origin and link to a stored drawing with /editor/<drawingId>, or to a blank one with /editor. Nothing to integrate; this is what most teams should do first.

2. Embed the component

CadEditorComponent takes a drawing id or DXF text and emits the DXF back when the user exports or leaves. 

{{ snippets.api }}
{{ snippets.template }}

Embedded mode. Leave the Supabase URL and anon key empty in the environment file. Route guards pass through, the account menu renders nothing, and a 401 from the API no longer redirects to a sign-in page: your application owns identity. Link users straight at /editor; the dashboard is not meant for this mode. If your app mints its own tokens, override the token source: 

{{ snippets.token }}

getToken() may return a string, null, or a promise of either. Your provider owns expiry; in embedded mode the editor will not navigate on a 401.

3. Hand a drawing over between pages

DrawingTransferService is an inbox that survives a page refresh. Set the payload, navigate to the editor, and it opens the drawing on start-up. Storage keys are prefixed cad.transfer.*. 

{{ snippets.transfer }}

Accepted payloads: DXF text (AC1032 headers are validated; older files still parse) and the JSON entity payloads produced by the cad-core exporters.
